# GPT-OSS-120B · Sonnet 4.6 · Opus 4.6 비교

2026-09-14, Windows, Orca 1.4.201, Node 24.19.0. **이번 두 작업에서는 Claude가 최초 시도에 모두 통과했고, GPT-OSS의 재시도까지 합치면 Claude보다 적은 토큰으로 완료했다.** 표본이 작으므로 일반적인 모델 우열이나 전체 업무 비용으로 확대하지 않는다.

## 조건

- 세 모델 모두 동일한 **Agy CLI**, 현재 인증, plan/sandbox, JSON 출력으로 호출했다. native Claude CLI와의 비교가 아니다.
- 동일 기준 커밋 `e06389b99646107e478349b2b19bdd7c9379128b`에서 만든 **Orca child worktree 3개**를 사용했다.
- 초기 입력 문자열의 SHA-256은 작업별로 세 모델 모두 같다. 모델별 기본 시스템 문맥·토크나이저는 다를 수 있다.
- 검증 캐시 재사용 함수와 조직도 유효성 검사 함수 두 개를 독립 호출했다. 파일·도구 사용 없이 완성된 ES 모듈을 반환하도록 했다.
- 검사 코드는 응답을 받은 후에만 작업 공간에 썼다. null·잘못된 타입·경계값·순서·순환·누락·입력 불변성 등을 검사했다. 생성 코드는 Node permission 모드에서 파일 읽기 범위를 제한해 실행했다.
- 최초 시도는 모델당 작업별 한 번. 실패한 GPT-OSS 조직 검사만 오류 설명을 추가하여 한 번 재시도했다. 재시도 입력은 최초 비교와 다르다.

토큰은 Agy JSON의 `usage` 실측값이다. 모든 호출에서 cache_read_tokens와 thinking_tokens는 0으로 보고됐다. 내부 추론이 없다는 별도 증거로 해석하지 않는다. 금액과 구독 할당량의 실제 차감량은 제공되지 않아 **비교 불가**다. 병렬 호출했으므로 표의 시간 합계는 전체 실험의 벽시계 시간이 아니다.

이번 완료 기준으로 GPT-OSS는 Sonnet보다 약 8.9%, Opus보다 약 11.1% 더 많은 토큰을 썼다. 단순 캐시 함수에서는 GPT-OSS가 한 번에 성공하면서 토큰도 적었다. 성공률·토큰·시간·구독 차감을 함께 봐야 하며, 토큰만 같다고 실제 금액도 같다고 할 수는 없다.

## 플러그인 적용

- GPT-OSS: 짧고 명확한 편집·인용·초안에 우선 사용.
- 일반 구현·복잡한 조건: 사용자가 선택한 Sonnet/Opus/Gemini 프로필 활용.
- 재시도: 고정 5회 대신 예제는 GPT-OSS 1회 후 선택된 프로필로 승격. 실제 작업별 누적 사용량으로 조정.
- 구독·모델은 조직 최초 구성에서 각 직급마다 선택하고 이후 저장값을 사용.

새 하네스의 별도 실제 실행도 확인했다. `prepare`가 네 번째 Orca child worktree를 만들고 GPT-OSS가 만료 경계 비교를 `>`에서 `>=`로 수정했다. **1회 / 11,845토큰 / 11.33초**, 외부 하네스의 경계 검사 통과. 이 결과는 위의 동일 과제 비교 합계에 포함하지 않는다.
