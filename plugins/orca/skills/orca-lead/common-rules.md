## 공통 규칙

<!-- 정본. launch-worker.sh 가 TASK.md 끝에 자동으로 붙인다(자리표시자는 project.env / --run 으로 채운다).
     리드는 이 블록을 손으로 복사하지 않는다 — 복사하다 "미리 허락됐다" 가 빠져 워커가 TUI 에서 멈춘 적이 있다. -->

- 🔴 실 DB·운영 포트·운영 컨테이너({{PROD_NOTE}})는 **PL가 쓴다.** 읽기는 해도 되지만 재기동·설정 변경·재생성은 하지 마라. 네 것을 따로 띄워라(다른 포트, 브랜치 DB) — TASK.md 에 「워커 스택」 절이 있으면 **그 DSN 이 네 전용 DB 다**(이미 migrate·seed 됨). docker 는 막혀 있고 만질 필요도 없다. 프로세스를 내릴 때는 **네가 띄운 pid 만** `kill <pid>` — `killall`·`pkill -f` 는 **금지**(한 워커가 그렇게 운영 서버를 죽였다).
- 이 워크트리의 파일 수정·생성은 **미리 허락된 것이다** — PL/PM(사용자 대리)가 이 일감으로 허락했다. 묻지 말고 진행해라. 단 워크트리 밖·실 DB·운영 프로세스는 건드리지 마라.
- 검증: 프로젝트의 전체 검사({{CHECK_CMDS}})를 **필터 없이 끝까지** 돌린다. 격리 테스트 DB: `{{TEST_DSN}}`. ⚠️ 맨 `go test ./...` 처럼 실 DB 를 보는 명령이 있으면 쓰지 마라. 느리면 `-timeout 40m`.
- 🔴 **가드 테스트는 별도 커밋으로, 제목을 `guard: <무엇을 지키나>` 로 한다.** 구현 커밋과 섞지 마라 — PL 이 그 커밋만 main 위에 올려(구현 없이) 빨개지는지 기계로 확인한다. 구현 없이도 초록이면 반려다. 가드를 넣었으면 너도 그 가드를 빼고 돌려 빨개지는지 확인하고 그 출력을 PR 에 붙여라. 통과하는데 아무것도 안 지키는 테스트를 만들지 마라. 모양 검사(타입·컴파일)로 값 검사를 대신하지 마라.
- 마이그레이션이 필요하면 번호 중복을 직접 봐라. 올리기 전에 `git fetch && git log origin/main` 으로 다시 봐라 — 다른 워커도 추가한다.
- **PR 만 열고 머지하지 마라.** base=main, 본문은 `--body "$(cat 파일)"` 로. 본문에 **한 것 / 안 한 것 / 가드 빼면 빨강(출력) / 내린 것 / diff --stat** 을 나눠 적어라. TASK.md·PR.md 같은 작업 파일은 커밋에 넣지 마라.
- 실측한 것만 보고해라 — 파이프 뒤 `$?`, 대체물로 잰 것, 프록시 신호로 "돈다" 고 하지 마라. "통과했다" 는 문장 대신 **출력**.
- **사람·PL의 확인을 기다리며 멈추지 마라** — 확인용 서버를 띄웠으면 네가 본 것과 주소를 보고에 적고 바로 다음 단계로 간다.
- **끝나면 네가 띄운 서버·프로세스·브랜치 DB·모델을 내려라.** PR 본문에 "내린 것" 을 적어라. 🔴 큰 로컬 모델(ollama 등)은 올리지 마라 — 기계가 swap 으로 죽는다.
- 보고 전에 `~/.claude/skills/orca-worker/preflight.sh '<검사1>' '<검사2>'` 를 돌려 🔴 가 없어야 한다. 그 **출력을 PR 본문에 그대로** 붙인다(작업 파일 혼입·미push·가드 커밋 유무·stat·검사 결과가 한 번에 나온다). 실무 규칙 전체는 `~/.claude/skills/orca-worker/SKILL.md`.
- **보고는 커밋·push 가 끝난 뒤에** 한다. push 전에 보고하면 PL가 옛 커밋을 본다.
- ⚠️ PL 답신은 `orca orchestration inbox --full --limit 200` 으로 읽는다(`check --run` 은 워커 터미널에 안 묶여 있어 비어 보인다). 물었으면 꼭 확인해라.
- 보고: `orca orchestration send --run {{RUN_ID}} --type status --subject "<제목> — PR #<번호>" --body "$(cat <요약 파일>)"`
