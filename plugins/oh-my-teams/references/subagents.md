# 서브에이전트 실행 규칙

역할이 자기 실행기(host)가 제공하는 서브에이전트를 언제 쓰고, 언제 별도 Worker 실행과 워크트리로 넘기는지를 정하는 규칙이다. 이 문서가 정본이며 pm과 worker 스킬, 이전 kickoff용 pl·senior·junior 스킬은 여기를 참조한다. 이전의 `assist` 명령은 2.11.0에서 이 규칙으로 대체되어 삭제되었다.

## 서브에이전트와 Worker

서브에이전트는 역할이 쓰는 실행기 안에서 그 역할의 호출로 뜨는 보조 실행이다. Claude Code의 서브에이전트와 Codex의 하위 에이전트가 그 예이며, OMT가 만든 역할이나 실행이 아니다. 다음 표가 어느 쪽을 쓸지 정한다.

| 일의 성격 | 실행 방식 |
|---|---|
| 조사, 초안 작성, 순차적인 좁은 편집이며 호출한 역할의 범위와 워크트리 안에서 끝나는 일 | 실행기의 서브에이전트 |
| 병렬 편집 | 별도 Worker 실행과 워크트리 |
| 자기 작업 계약과 커밋·보고가 필요한 일 | 별도 Worker 실행과 워크트리 |
| 정식 독립 검토 | 별도 Worker 실행과 워크트리 |

한 워크트리에서 편집하는 실행은 한 번에 하나만 허용한다. 호출한 역할이 직접 편집하는 동안에는 서브에이전트가 같은 워크트리를 편집하지 않고, 서브에이전트에게 편집을 맡겼다면 그 역할은 결과를 받을 때까지 편집을 멈춘다. 편집이 겹쳐야 하는 일은 병렬 편집이므로 별도 Worker 실행으로 나눈다.

서브에이전트는 OMT 역할이나 승인자가 아니다. 서브에이전트가 낸 결과는 `review-record`의 검토로도, 수용의 근거로도 쓰지 않는다. 독립 검토는 구현과 다른 실행 ID를 가진 Worker가 맡는다.

## 호출한 역할의 책임

서브에이전트에게 맡긴 범위와 그 결과는 호출한 역할이 소유한다. 호출한 역할은 서브에이전트가 낸 내용을 그대로 통합하지 않고 변경 범위, 검사 결과와 수용 기준을 직접 확인한 뒤에 자기 결과로 삼는다. 확인하지 못한 내용은 근거가 있는 것처럼 보고하지 않는다. 작업 계약의 `files` 밖을 건드린 결과는 받아들이지 않고 되돌린다.

## 서브에이전트에게 금지되는 일

호출하는 역할은 위임할 때 다음을 지시문에 함께 적는다.

- 워크트리, 브랜치, 커밋을 만들지 않는다.
- 다른 서브에이전트나 Worker에게 다시 위임하지 않는다.
- 사용자에게 직접 보고하거나 질문하지 않고, 결과를 호출한 역할에게만 돌려준다.

## 서브에이전트를 쓸 수 없을 때

실행기가 서브에이전트를 제공하지 않거나 이번 세션에서 쓸 수 없으면, 역할이 그 일을 직접 수행한다. PM은 일이 별도 Worker의 몫이면 Worker를 배정한다. OMT는 서브에이전트를 대신할 실행기를 만들지 않으며, 서브에이전트가 있다고 가정하는 런타임 경로도 두지 않는다.

## 워크트리 순서

Worker 실행이 필요하다고 판단한 뒤에는 워크트리를 다음 순서로 정한다. 절차와 증명 조건은 [`orca-runtime.md`](orca-runtime.md)의 `role-worktree-create` 설명을 따르며, 이 문서는 순서만 정한다.

1. 같은 역할의 기존 워크트리를 안전하게 재사용할 수 있는지를 먼저 확인한다. 확인은 `role-worktree-create --worktree <id>`가 하는 기존 증명을 그대로 쓰고, 이 문서나 스킬이 별도의 판정 기준을 만들지 않는다.
2. 수정과 재시도는 원래 작업한 워크트리에서 한다.
3. 재사용이 불가능하고 독립 실행이 필요할 때에만 새 워크트리를 만든다.

프로세스 감독, 무응답 판정, 자원 회수는 Orca의 기능이다. 이 규칙은 그 기능을 다시 구현하지 않으며, 감독과 회수는 [`orca-runtime.md`](orca-runtime.md)의 절차를 따른다.

## 이전 조직 파일의 `assistants`

2.10.x까지의 조직 파일에는 `assist` 명령의 허용 목록인 `assistants`가 들어 있을 수 있다. 2.11.0에서 이 설정은 지원이 끝났으며 다음과 같이 처리한다.

- 그 키가 남아 있는 조직 파일도 계속 유효하며, 이전과 같이 읽힌다. 키의 내용은 검증하지 않는다.
- 키는 어떤 동작도 바꾸지 않는다. 역할 배정, 프로필 선택, 자문 허용 목록과 사용량 집계에 영향을 주지 않는다.
- 런타임은 파일을 읽을 때 그 파일을 다시 쓰지 않는다. 정리는 사용자가 파일을 직접 고치거나 다음 저장에서 이루어진다.
- 다음에 저장되는 revision에서는 `assistants` 키가 빠진다. `adjust`가 이전 파일을 읽어 그대로 저장해도 새 revision에는 이 키가 없으며, 이전 revision은 `history`에 원본 그대로 보존된다.
- 새 조직에는 이 키를 쓰지 않는다.

이전 `assist` 명령이 남긴 `assists` 상태 디렉터리의 보고서는 사용량 기록으로만 읽힌다. 새 보고서는 만들어지지 않는다.
