# 사용자 선택 질문 계약

스킬이 사용자에게 결정을 물을 때 따르는 규칙이다. 이 문서가 정본이며 `form`, `adjust`, `kickoff`, `close`가 여기를 참조한다.

## 호스트 능력으로 방식을 정한다

호스트마다 질문 수단이 다르므로 특정 도구 이름을 전제하지 않는다. **현재 대화에서 구조화된 선택 도구를 실제로 사용할 수 있는지 확인한 뒤 방식을 고른다.**

| 상황 | 방식 |
|---|---|
| 구조화된 선택 도구를 쓸 수 있다 | 그 도구로 묻는다. 한 번의 호출에 관련된 질문을 함께 담는다. |
| 쓸 수 없다 | 번호를 매긴 선택지를 본문에 적고 한 번에 묻는다. |

Claude Code에서는 `AskUserQuestion`이 이 조건을 충족한다. 질문은 한 번에 네 개까지, 선택지는 질문마다 두 개에서 네 개까지 담을 수 있고, 자유 입력을 위한 항목은 호스트가 자동으로 붙이므로 직접 만들지 않는다. 여러 항목을 함께 고르게 하려면 그 질문만 다중 선택으로 표시한다.

Codex CLI에는 **이 용도로 확인된 도구가 없다.** 0.154.0 기준 `codex features list`의 `default_mode_request_user_input`은 `under development`이고 기본값이 꺼져 있다. `auth_elicitation`과 `tool_call_mcp_elicitation`은 stable이지만 각각 인증과 MCP 도구 호출에만 쓰이므로 구성 대화를 대신하지 않는다. 따라서 Codex에서는 번호를 매긴 선택지 방식을 쓰고, 도구가 있는 것처럼 보고하지 않는다. 이 판단은 설치된 CLI에서 다시 확인할 수 있으며, 나중에 해당 기능이 stable이 되면 첫 번째 방식으로 옮긴다.

## 어느 방식이든 지키는 것

1. **묻기 전에 확인한다.** 저장된 조직 파일, 프로젝트 상태, 설치된 CLI의 모델 목록에서 답을 얻을 수 있으면 묻지 않는다. 이미 저장된 구독 선택은 다시 묻지 않는다.
2. **한 번에 묻는다.** 서로 의존하지 않는 결정을 여러 차례에 나눠 묻지 않는다. 앞선 답에 따라 선택지가 달라지는 결정만 뒤로 미룬다.
3. **선택지는 확인된 값으로만 만든다.** 모델 ID는 `agy models`와 각 CLI의 카탈로그에서 읽은 것을 쓰고, 확인하지 못한 조합을 선택지에 넣지 않는다.
4. **권장값을 답으로 삼지 않는다.** 추천은 선택지 설명에 적고, 사용자가 고르지 않은 값을 기본값으로 저장하지 않는다. 답을 얻지 못하면 그 항목을 비운 채 진행하지 말고 멈춘다. 이 규칙은 스킬이 묻는다고 정한 항목에 적용된다. 스킬이 **묻지 않고 정한다고 명시한** 운영 값은 사용자의 답을 대신하는 값이 아니므로 예외이며, 그런 값은 사용자가 고른 것보다 더 많은 호출·계정·권한을 쓰지 않아야 하고, 저장한 뒤 무엇을 그렇게 정했는지와 어디서 바꾸는지를 알린다.
5. **선택의 결과를 함께 적는다.** 각 선택지에는 그것을 고르면 무엇이 저장되고 무엇이 달라지는지 한 문장으로 적는다. 되돌리기 어려운 결정은 그 사실을 명시한다.
6. **자유 입력을 받는다.** 선택지에 없는 값을 사용자가 말하면 그대로 받아 검증한다. 목록에 없다는 이유로 거절하지 않는다.

## 답을 받은 뒤

사용자의 답은 검증 전까지 입력일 뿐이다. 프로필, 모델 ID, 추론 강도는 저장하기 전에 런타임 검증을 거치고, 거부되면 정확한 이유와 함께 그 항목만 다시 묻는다. 구성 대화 전체를 처음부터 다시 시작하지 않는다.
