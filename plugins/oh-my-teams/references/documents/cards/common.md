# 공통 규칙

여섯 종류의 문서에 공통으로 적용하는 규칙입니다. 종류별 필드와 규칙은 같은 디렉터리의 카드에 있습니다.

## 전달과 식별

- `body`: YAML 1.2 단일 문서를 사용합니다.
- `tool_arguments`: 호스트와 Orca 도구가 요구하는 기존 인자 형식을 유지합니다.
- `identity`: id에는 작성 세션 안에서 중복되지 않는 문서 식별자를 사용합니다. issuer.session_id에는 호스트가 제공하는 실제 실행 식별자를 사용합니다. 식별자를 확인할 수 없다면 임의의 값을 만들어 유효한 보고서라고 주장하지 않습니다.
- `timestamps`: issued_at과 observed_at에는 시간대가 포함된 RFC 3339 시각을 사용합니다.
- `response`: review_result, completion_report와 interruption_report의 in_reply_to에는 원래 요청의 id를 그대로 넣습니다.
- `subject`: subject.worktree_id에는 Orca에서 확인한 전체 워크트리 ID를 넣습니다. commit에는 축약하지 않은 Git 객체 ID를 넣습니다. auditor 요청과 결과에는 commit과 implementation_session_id가 모두 필요합니다. 작업 요청에는 시작 커밋을, 완료 보고에는 검증한 최종 커밋을, 중단 보고에는 마지막으로 확인한 커밋을 넣습니다.

## YAML 작성

- 모든 매핑 키는 문자열이어야 합니다.
- 문자열, 유한한 숫자, 불리언, null, 배열과 객체만 사용합니다.
- 정수는 JavaScript에서 손실 없이 표현할 수 있는 범위로 제한합니다.
- 중복 키, 앵커, 별칭, 병합 키와 명시적 태그를 사용하지 않습니다.
- 문서 하나의 크기는 백만 UTF-16 코드 단위, 중첩은 40단계로 제한합니다.
- 긴 설명에는 리터럴 블록을 사용하고, 중요한 내용은 주석에 넣지 않습니다.
- 필수 항목을 생략하거나 정의되지 않은 필드를 추가하지 않습니다.
- 예제의 식별자와 관측값은 가상의 값이므로 실제 보고서에 그대로 사용하지 않습니다.

## 사용자에게 보여줄 때

- `input`: 구조와 의미를 검증한 동일한 JSON 호환 객체를 사용합니다.
- `output`: 외부 자원 없이 열 수 있는 UTF-8 단일 HTML 파일을 생성합니다.
- YAML을 파싱한 뒤 스키마와 의미 규칙을 검사하고, 실패하면 변환을 중단합니다.
- JSON은 같은 데이터의 직렬화 결과이며 HTML과 함께 별도의 편집 정본으로 관리하지 않습니다.
- 모든 문서 값은 HTML 텍스트로 이스케이프하고 스크립트나 실행 가능한 링크로 삽입하지 않습니다.
- 근거, 불확실성, 대상 커밋과 관측 시각을 HTML에서도 생략하지 않습니다.
- 호스트가 HTML 파일을 표시하거나 첨부할 수 있으면 생성한 파일을 전달하고 채팅에는 짧은 요약을 남깁니다.
- HTML 표시를 지원하지 않는 호스트에서는 제약을 밝히고 채팅으로 요약합니다.
- 플러그인 설치만으로 저장소 개발용 변환 명령이 설치됐다고 가정하지 않습니다.
