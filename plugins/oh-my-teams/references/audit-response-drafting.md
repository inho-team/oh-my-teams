# 감사 응답 초안 시험 운영

`lawyer`는 감사 이의를 검토하고 응답 초안을 준비하는 보조 실행의 작업 이름이다. 현재 OMT 조직의 역할이나 감사 판정자가 아니다. 기존 `audit-response` 권한은 브리프 체크포인트의 이사와 결과 체크포인트의 PM에게 그대로 있다. 보조 실행은 응답을 기록하거나 감사에게 판정을 요구하지 않는다.

## 적용 시점과 실행 방식

감사가 구체적인 이의를 기록했고, 책임자가 주장과 증거를 대조하는 데 도움이 필요할 때만 사용한다. 자료 조사와 초안 작성이 같은 작업 범위 안에서 끝나면 실행기가 제공하는 서브에이전트를 사용한다. 별도의 작업 계약, 병렬 편집 또는 정식 독립 검토가 필요하면 [서브에이전트 실행 규칙](subagents.md)에 따라 Worker를 배정한다. 실행기가 서브에이전트를 제공하지 않으면 책임자가 직접 검토한다.

보조 실행에는 해당 이의, 원장의 대상 항목, 사용자 원문 또는 확정 브리프, 관련 구현과 증거의 읽기 경로를 제공한다. 기존 응답이나 감사 판정이 있으면 초안을 독립적으로 만든 뒤 비교한다. 다른 kickoff의 자료를 섞지 않고, 현재 이의가 가리키는 기준과 결과를 먼저 확인한다.

## 보조 실행에 전달할 지시

다음 지시를 해당 kickoff의 경로와 이의 식별자로 채워 전달한다.

> 감사 이의 `<이의 식별자>`에 대한 응답 초안을 준비하십시오. 원장의 대상 항목과 사용자 원문, 이의의 각 주장, 현재 구현과 증거를 대조하십시오. 타당한 지적은 인정하고 필요한 수정이나 사용자 확인을 제안하십시오. 다툴 지적은 반증 가능한 근거와 확인한 파일 또는 기록을 제시하십시오. 확인하지 못한 사실과 남은 위험을 분리해서 적으십시오. 이의별 판단, 근거, 제안하는 응답 문장, 필요한 후속 조치를 책임자에게 보고하십시오. 감사 판정이나 완료를 선언하지 말고, `audit-response`와 다른 런타임 기록 명령을 실행하지 마십시오. 워크트리·브랜치·커밋을 만들지 말고, 사용자에게 직접 묻거나 보고하거나 다시 위임하지 마십시오.

## 책임자의 검토와 기록

이사 또는 PM은 초안의 인용 경로와 현재 내용을 직접 확인한다. 사용자 요구와 구현이 어긋났다면 방어 논리를 먼저 쓰지 않고 수정 또는 확인 절차를 정한다. 응답에는 이의의 각 쟁점에 대한 판단과 실제로 확인한 근거를 넣으며, 앞으로 할 일을 이미 끝낸 일처럼 적지 않는다. 근거가 부족하면 추가 조사나 수정 뒤에 응답한다.

책임자만 자신의 권한으로 `audit-response`를 기록한다. 이후 설득 여부는 감사가 `audit-ruling`으로 판정한다. 감사가 수용하지 않으면 지적과 근거를 다시 검토하며, 양측이 합의했다는 문구로 미해결 이의를 닫지 않는다. 명령과 신원 검증의 정본은 [감사 역할](../skills/auditor/SKILL.md)과 `scripts/audit.mjs`를 따른다.

## 시험 결과를 판단하는 기준

첫 실제 적용에서는 이의의 쟁점을 빠뜨리지 않았는지, 근거를 현재 파일에서 재확인할 수 있는지, 타당한 지적을 인정했는지, 책임자가 초안을 얼마나 고쳤는지, 감사의 후속 판정과 재작업 횟수가 어떠했는지를 기록한다. 보조 실행이 응답 품질이나 처리 시간을 개선했다는 근거가 쌓이기 전에는 조직 역할, 권한, 게이트 또는 별도 저장 형식을 추가하지 않는다.
