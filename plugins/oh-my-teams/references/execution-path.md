# 실행 경로 선택

이 문서는 요청을 현재 세션에서 직접 처리할지, 기존 kickoff를 재개할지, 새 kickoff를 시작할지 정하는 기준이다. `kickoff`는 팀 실행을 요청한 경우에만 사용한다. 일반적인 개발 요청이라는 이유만으로 조직을 결성하거나 kickoff를 시작하지 않는다.

| 요청과 현재 상태 | 실행 경로 | 새 워크트리 |
|---|---|---|
| 사용자가 직접 수정을 요청하거나 kickoff를 사용하지 말라고 했고, 별도 팀 실행이 필요하지 않음 | 현재 세션과 체크아웃에서 직접 작업한다. 저장소의 브랜치·검사·병합 규칙을 따른다. | 만들지 않는다. |
| 같은 목표의 kickoff가 이미 등록되어 있음 | 등록된 PM 세션과 워크트리에서 재개한다. | 새 PM 워크트리를 만들지 않는다. |
| 사용자가 팀을 구성하여 지속 감독하라고 요청했고 기존 kickoff가 없음 | `kickoff`로 PM에게 인계한다. | kickoff당 PM 워크트리 하나를 만든다. |

단순 편집, 조사, 일반 QA와 회귀 검사만으로는 kickoff가 필요하지 않다. 이미 진행 중인 kickoff 안에서도 읽기 전용 확인을 위한 workflow task와 Worker 워크트리를 만들지 않는다. PM이 직접 작업할 수 있는 범위는 PM 워크트리에서 끝내고, 독립 편집이나 정식 독립 검토가 필요할 때에만 Worker 실행을 검토한다. Worker 워크트리는 검증된 기존 후보를 먼저 재사용하며, 새 워크트리는 별도 격리가 필요한 경우에만 만든다. 구체적인 재사용 증명과 생성 거부는 런타임이 결정한다.

사용자가 직접 처리하라고 지정한 요청에는 OMT의 Director·PM 역할 계약이 적용되지 않는다. 이때 `form`, `kickoff`, `workflow-create`, `role-worktree-create`, `prepare`를 실행하지 않는다. 진행 중인 kickoff의 상태를 임의로 가져오거나 수정하지 않는다. 팀 실행을 명시적으로 요청했을 때에는 `kickoff-show`로 같은 목표가 등록되어 있는지 먼저 확인한다.
