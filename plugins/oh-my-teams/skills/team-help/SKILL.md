# 팀 도움말

현재 설치된 oh my teams 플러그인의 `skills/*/SKILL.md` frontmatter를 읽고 스킬 목록을 확인한다. 기억에 의존하여 존재하지 않는 스킬을 표시하지 않는다. 사용자의 프로젝트나 조직 설정을 변경하지 않으며, 도움말 조회만으로 `team-form`이나 `team-kickoff`를 실행하지 않는다.

## 표시 순서

다음 세 표를 순서대로 보여 준다.

1. 사용자가 직접 호출하는 생애주기 스킬을 실제 작업 순서로 표시한다.
2. kickoff가 내부에서 사용하는 역할 스킬을 보고 구조 순서로 표시한다.
3. 이전 이름을 지원하는 호환 진입점을 표시한다.

각 표에는 `스킬`, `용도`, `사용 시점` 열을 포함한다. 설치된 스킬의 description과 본문을 근거로 한두 문장 안에서 설명한다. 호출 형식은 현재 호스트에 맞게 표시한다. Claude Code에서는 `/oh-my-teams:<skill>`, Codex에서는 `$oh-my-teams:<skill>` 또는 현재 클라이언트가 제공하는 실제 호출 형식을 사용한다. 확인할 수 없는 호출 문법을 추측하지 않는다.

생애주기 표의 기본 순서는 다음과 같다.

| 스킬 | 용도 | 사용 시점 |
|---|---|---|
| `team-help` | 설치된 스킬과 작업 흐름을 안내한다. | 어떤 명령을 사용할지 확인할 때 사용한다. |
| `team-form` | 재사용할 상설 조직을 결성한다. | 프로젝트에서 조직을 처음 구성할 때 사용한다. |
| `team-kickoff` | 하나의 개발 Goal과 실행 팀을 시작하거나 재개한다. | 팀에 개발 목표를 맡기고 완료까지 지속해서 진행할 때 사용한다. |
| `team-status` | 조직과 현재 Goal·실행 팀·워크트리 상태를 표시한다. | 진행 상황이나 중단 상태를 확인할 때 사용한다. |
| `team-adjust` | 상설 조직의 역할·인원·구독·모델을 조정한다. | 이후 kickoff에 적용할 조직 구성을 바꿀 때 사용한다. |
| `team-close` | 성공한 Goal의 전달·병합·자원 정리를 완료한다. | 수용 기준을 충족한 작업을 성공으로 종료할 때 사용한다. |
| `team-disband` | 실패·취소된 실행 팀을 해체하고 기록을 보존한다. | 작업을 성공으로 종료할 수 없거나 사용자가 취소할 때 사용한다. |

역할 스킬에는 `pm`, `pl`, `senior`, `junior`, `intern`을 표시하고, `intern`의 사용자 표시 명칭이 Worker라는 점을 함께 밝힌다. 호환 표에는 실제로 설치된 `team-setup`, `team-show`, `team-edit`, `org-setup`, `org-show`, `org-edit`, `director`만 표시한다.

마지막에는 일반적인 시작 흐름을 한 줄로 안내한다.

```text
team-form → team-kickoff → team-status → team-close
                                      └→ team-disband
```

조직이 이미 구성되었으면 `team-form`을 생략할 수 있다고 덧붙인다. 사용자가 특정 목적을 함께 말했으면 표를 표시한 뒤 가장 적절한 스킬 하나를 추천하되 자동으로 실행하지 않는다.
