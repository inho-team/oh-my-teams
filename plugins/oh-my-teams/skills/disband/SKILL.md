# 작업 중단

현재 워크트리의 소유 세션이 중단 사유와 마지막으로 확인한 커밋, 미전달 변경과 실행 중인 자식 세션을 기록한다. Orca에서 정확한 세션과 워크트리 ID를 확인한 뒤, 사용자가 중단을 요청한 실행만 종료한다.

세션의 생존이나 삭제 결과를 확인할 수 없으면 [실패 상황의 판단 기준](../../references/failure-handling.md)에 따라 관측 오류를 실제 종료로 바꾸지 않고 기존 대상을 보존한다.

수정된 파일, 추적되지 않거나 무시된 중요한 파일, 미전달 커밋, 생존 상태가 불명확한 터미널이 있는 워크트리는 보존한다. 자식 세션이 종료됐고 Git 상태가 깨끗하며 결과가 이미 전달된 워크트리만 Orca에서 인스턴스 식별자를 재확인한 뒤 회수한다. 현재 세션이 서 있는 워크트리는 스스로 제거하지 않는다. 남은 결과와 복구 방법을 사용자에게 보고하고, 네이티브 Goal은 실제 중단 사유에 맞춰 처리한다.

중단·인계 보고는 [YAML 문서 규칙](../../references/documents/protocol.yaml)과 [JSON Schema](../../references/documents/document.schema.json)의 `interruption_report`로 작성한다. [중단 보고 예제](../../references/documents/interruption-report.example.yaml)의 가상 값을 실제 값으로 바꾼다. `in_reply_to`에 원래 작업 요청을 연결하고, 마지막으로 확인한 커밋·미전달 변경·정확한 세션과 인스턴스·재개 절차를 남긴다. 사용자 허가 없이 종료 조치를 기록하지 않으며, 생존 상태를 확인하지 못한 세션은 종료됐다고 기록하지 않는다. 원래 요청이 문서로 없으면 실제 사용자 요청에서 작업 양식을 구성한다. 사용자에게 보여주는 문서는 검증한 같은 데이터에서 HTML로 생성하며, HTML 표시가 불가능하면 제약과 요약을 전달한다.
