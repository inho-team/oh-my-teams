# 팀 도움말

아래 안내문을 그대로 출력한다. 스킬 파일을 읽어 표를 다시 만들지 않는다. 이 표는 설치된 스킬 목록과 일치하도록 `tests/code-quality.test.mjs`가 검사하므로, 매번 다시 조사하면 같은 결과를 더 비싸게 얻을 뿐이다.

표는 스킬 이름만 담는다. 호스트 접두사는 마지막 추천 문장에서만 붙이며, Claude Code는 `/oh-my-teams:<skill>`, Codex는 `$oh-my-teams:<skill>`을 사용한다. 확인할 수 없는 호출 문법은 추측하지 않는다.

도움말 조회만으로 `form`이나 `kickoff`를 실행하지 않으며, 사용자의 프로젝트나 조직 설정을 변경하지 않는다. 사용자가 특정 목적을 함께 말했으면 표를 출력한 뒤 가장 적절한 스킬 하나를 추천하되 자동으로 실행하지 않는다.

## 생애주기 스킬

사용자가 직접 호출하며, 실제 작업 순서대로 나열했다.

| 스킬 | 용도 | 사용 시점 |
|---|---|---|
| `help` | 설치된 스킬과 작업 흐름을 안내한다. | 어떤 명령을 사용할지 확인할 때 사용한다. |
| `form` | 재사용할 상설 조직을 결성한다. | 프로젝트에서 조직을 처음 구성할 때 사용한다. |
| `kickoff` | 하나의 개발 Goal과 실행 팀을 시작하거나 재개한다. | 팀에 개발 목표를 맡기고 완료까지 지속해서 진행할 때 사용한다. |
| `status` | 조직과 현재 Goal·실행 팀·워크트리 상태를 표시한다. | 진행 상황이나 중단 상태를 확인할 때 사용한다. |
| `adjust` | 상설 조직의 역할·인원·구독·모델을 조정한다. | 이후 kickoff에 적용할 조직 구성을 바꿀 때 사용한다. |
| `close` | 성공한 Goal의 전달·병합·자원 정리를 완료한다. | 수용 기준을 충족한 작업을 성공으로 종료할 때 사용한다. |
| `disband` | 실패·취소된 실행 팀을 해체하고 기록을 보존한다. | 작업을 성공으로 종료할 수 없거나 사용자가 취소할 때 사용한다. |

## 역할 스킬

`kickoff`가 내부에서 사용하며 보고 구조 순서대로 나열했다. 직접 호출하는 대신 `kickoff`를 사용한다.

| 스킬 | 용도 | 사용 시점 |
|---|---|---|
| `pm` | 요청을 분석해 계획하고 배정하며 결과를 책임진다. | kickoff가 목표를 받아 전체를 지휘할 때 사용한다. |
| `pl` | 작업을 분할하고 의존성과 워크트리를 배정한다. | 병렬 작업의 순서와 통합을 관리할 때 사용한다. |
| `senior` | 설계를 정하고 중요한 변경의 의미를 검토한다. | 반복 실패와 통합 충돌을 해결할 때 사용한다. |
| `junior` | 기능 구현을 책임지고 Intern의 실무를 통합한다. | 실제 코드 변경을 맡길 때 사용한다. |
| `intern` | 제한된 파일 편집과 검색 인용, 반복 실무를 수행한다. | 범위가 좁고 검증이 쉬운 작업에 사용한다. |

## 지원 스킬

| 스킬 | 용도 | 사용 시점 |
|---|---|---|
| `fluent-korean` | 한국어 답변과 보고서의 문장을 명확하게 다듬는다. | 한국어로 설명하거나 결과를 보고할 때 사용한다. |

## 2.0.0에서 삭제된 이름

아래 이름은 더 이상 설치되지 않는다. **별칭으로도 남아 있지 않으므로 호출하면 스킬을 찾을 수 없다.** 사용자가 이 이름으로 요청하면 지금 이름을 알려 준 뒤 그 스킬을 실행한다.

| 삭제된 이름 | 지금 이름 |
|---|---|
| team-form, team-setup, org-setup | `form` |
| team-status, team-show, org-show | `status` |
| team-adjust, team-edit, org-edit | `adjust` |
| team-kickoff | `kickoff` |
| team-close | `close` |
| team-disband | `disband` |
| team-help | `help` |
| director | `pm` |

## 일반적인 흐름

```text
form → kickoff → close
              └→ disband
```

한 프로젝트에서 활성 kickoff는 하나다. `kickoff`를 선언한 세션은 실행을 감독할 워크트리를 만들어 목표를 넘기고, 이후 `status`·`close`·`disband`는 넘긴 쪽에서 수행한다.

`status`와 `adjust`는 이 흐름의 단계가 아니라 언제든 호출할 수 있다. `status`는 현재 상태를 조회만 하고, `adjust`는 이후 kickoff에 적용할 조직을 바꾼다.

조직이 이미 구성되어 있으면 `form`은 생략할 수 있다.
