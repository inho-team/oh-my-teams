# 개발 문서 안내

최초 분석의 기준은 `b8e7706`이다. 개발 문서와 검사 범위 표에는 `fix/input-and-alias-validation`의 후속 구현을 반영했으며, 분석 보고서에는 최초 재현과 후속 확인을 구분했다. 후속 확인은 미커밋 작업 파일을 대상으로 하므로 병합된 제품의 검증 결과로 간주하지 않는다.

현재 제품은 Orca 워크트리의 소유 세션을 중심으로 동작하는 3.x 스킬 패키지다. 설치되는 규칙은 `plugins/oh-my-teams/` 안에서 관리하고, 이 디렉터리에는 개발 설명과 분석을 둔다.

| 문서 | 읽는 목적 |
|---|---|
| [프로젝트 분석과 개선 계획](PROJECT_ANALYSIS.md) | 복잡도와 버그 위험의 근거, 재현 결과, 후속 개발 순서를 확인한다. |
| [구조 안내](ARCHITECTURE.md) | 제품·개발 도구·외부 호스트의 경계와 정본을 확인한다. |
| [개발 도구와 공통 예제](DEVELOPMENT.md) | 모듈 책임과 포트, 공개 API, 변경·검증 절차를 확인한다. |
| [코드와 스킬 검증](CODE_QUALITY.md) | 자동 검사가 보장하는 범위와 놓치는 범위를 확인한다. |
| [실패 대응 시나리오](SCENARIO_CHECKS.md) | 실제 호스트 검증에 필요한 입력·판정·증거를 준비한다. |

작업 소유권의 정본은 설치되는 [세션 소유권 구조](../plugins/oh-my-teams/references/architecture.md)이며 실패 판단의 정본은 [실패 상황의 판단 기준](../plugins/oh-my-teams/references/failure-handling.md)이다. `docs/`의 분석이나 제안을 설치된 제품의 기능으로 취급하지 않는다.
