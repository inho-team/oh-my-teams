# 감사 응답 초안 시험 결과

2026-10-10에 `lawyer`를 별도 OMT 역할로 등록하기 전에, 기존 `audit-response`의 초안 작성에 보조 실행을 사용하는 방식을 시험했다. 실행 절차는 [`audit-response-drafting.md`](../../plugins/oh-my-teams/references/audit-response-drafting.md)에 정리했다.

## 시험 자료와 방법

종료된 #139 kickoff의 브리프 감사 이의 `bcd2bc8c-b0d1-4fdf-bd51-4fe382fb90d9`를 사용했다. 감사는 `c1.userVisible:false`가 사용자 확인 경로를 빠뜨린다고 지적했다. 자료는 주인 체크아웃의 `.omt/audits/8a4563d2e846e5a13809a2d6598db5379ad4d1bfd4752d78804bb16a4030031e.json`, `.omt/briefs/139-auditor-2026-09-27.md`, `.omt/requirements-drafts/8a4563d2e846e5a13809a2d6598db5379ad4d1bfd4752d78804bb16a4030031e.json`에서 확인했다.

첫 보조 실행은 자료를 찾는 과정에서 보관된 응답과 판정의 일부를 보았다. 따라서 그 결과는 독립적인 초안 평가에서 제외했다. 두 번째 보조 실행에는 이의, 당시 브리프, `c1`과 `c2`만 추린 자료를 제공하고 다른 파일을 열지 않도록 했다. 이 실행은 보관된 응답과 판정을 받지 않은 상태에서 초안을 만들었다.

## 관찰 결과

두 번째 초안은 `c1`이 사용자 확인 경로를 제약한다는 핵심 지적을 인정했다. 이번 원장에 축소 사례가 없다는 사실과 제품이 보장해야 할 동작을 구분했고, `c2`와 분류가 다른 이유에는 근거가 부족하다고 판단했다. 제공되지 않은 이슈 원문, PM의 판정 원칙, 구현 결과와 분류 동기는 확인되지 않았다고 명시했다. 이사에게는 `c1`의 분류를 다시 판단하고, 필요하면 사용자 제시·확인을 실행하되 아직 수행한 것으로 주장하지 말라는 응답 초안을 제안했다.

보관된 실제 응답은 이의를 인정하고 `c1.userVisible`을 `true`로 수정했으며, 감사는 그 수정과 근거를 확인한 뒤 `persuaded`로 판정했다. 시험 초안의 방향은 이 기록과 맞지만, 보조 실행이 실제 수정이나 사용자 제시를 수행한 것은 아니다. 이 사례만으로 처리 시간이나 감사 통과율의 개선을 입증할 수도 없다.

## 운영 판단

보조 실행은 이의의 쟁점을 나누고 근거가 부족한 주장을 유보하는 초안을 만들 수 있었다. 현재는 이사 또는 PM이 자료를 직접 재확인하고 자신의 권한으로 응답하며, 감사가 판정하는 절차를 유지한다. 다음 실제 이의에서는 책임자가 초안을 얼마나 수정했는지와 재작업 횟수, 검증 가능한 근거의 누락 여부를 기록한 뒤 독립 역할의 필요성을 다시 판단한다.
