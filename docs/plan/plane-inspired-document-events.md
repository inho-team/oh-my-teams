# 문서 이벤트의 저장과 전달

이 기능은 `saveDocument`가 확정한 문서 revision에서 `document.created`, `document.revised`, `document.state-changed` 이벤트를 생성합니다. 첫 revision에는 생성 이벤트를 기록하고, 후속 revision에는 수정 이벤트를 기록합니다. 상태가 실제로 바뀌었을 때에만 상태 변경 이벤트를 추가합니다. 같은 `requestId`로 재시도하면 이미 확정된 revision을 반환합니다. `task-comment` 문서의 저장과 이벤트 소비는 거부합니다.

## 저장과 복구

저널은 revision, 이벤트 파일, 미전달 큐 항목, 현재 revision을 하나의 적용 단위로 묶습니다. 적용 도중 중단되어 이벤트 파일만 남아도 다음 저장 과정에서 저널을 다시 적용하여 큐 항목을 복원합니다. 워크플로 소비자는 이벤트 ID를 상태와 이벤트 파일에 함께 기록하며, 같은 ID를 다시 받으면 적용하지 않습니다.

## 전달과 수신 확인

`doc-event-deliver`는 Orca 어댑터에서 현재 터미널에 연결된 Run을 확인하고 미전달 큐의 이벤트를 보냅니다. 전송 호출이 성공하면 **송신 측**이 로컬 수신 확인 파일을 쓴 뒤 큐 항목을 제거합니다. 이 파일은 수신 측의 처리 완료를 증명하지 않습니다. 전송이 실패하거나 수신 확인 파일을 쓰지 못하면 큐 항목을 남깁니다. 이미 수신 확인 파일이 있으면 같은 큐 항목을 다시 보내지 않고 제거합니다. Run과 터미널 주소는 전달 경로이며 문서 작성자의 신원 증거가 아닙니다.

전송 호출이 성공한 뒤 수신 확인 파일을 쓰기 전에 중단되면 재시도 과정에서 같은 이벤트를 다시 보낼 수 있습니다. 소비 측은 이벤트 ID로 중복 적용을 막습니다. 파일 기록은 임시 파일을 같은 디렉터리에서 이름 변경하는 방식으로 부분 JSON 노출을 줄이지만, `fsync`를 수행하지 않으므로 전원 손실 뒤의 영속성이나 정확히 한 번만 전달되는 동작은 보장하지 않습니다.
