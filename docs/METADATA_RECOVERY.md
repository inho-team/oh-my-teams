# 중단 후 메타데이터 복구

3.0.8은 기존 JSON 경로와 개별 파일을 읽는 계약을 유지한다. 정본은 `package.json`이며 별도 트랜잭션 저장소, 배포 포인터나 Orca 실행 등록부를 만들지 않는다. 중단 뒤에는 과거 스냅샷을 무조건 되돌리는 대신 현재 입력으로 다시 계획하여 정본 버전으로 수렴한다.

## 쓰기와 복구 경계

모든 JSON과 버전 형식을 읽고 검증한 다음 각 파일을 교체한다. 교체할 내용은 같은 디렉터리의 고유 임시 파일에 기록하고 권한을 보존한다. [Node의 `fsyncSync`](https://nodejs.org/api/fs.html#fsfsyncsyncfd)를 호출한 뒤 원본 내용을 다시 비교하고 이름 변경으로 교체한다. 기록·데이터 반영 실패 시 대상은 교체하지 않으며 이미 교체한 파일은 관측된 내용이 이 실행의 결과와 같을 때만 역순 복구한다.

이 절차는 파일 데이터의 반영을 요청하지만 디렉터리 항목의 동기화, 저장 장치의 캐시 보장이나 여러 JSON의 원자적 가시성을 제공하지 않는다. 전원 장애 때의 내구성은 파일 시스템과 장치에 의존한다. 비교와 교체 사이에 외부 프로그램이 쓰는 경쟁도 남아 있으므로 한 번에 하나의 실행자만 버전을 편집하고 동기화해야 한다.

## 중단 뒤 수행할 절차

1. 이전 동기화 실행이 끝났고 같은 파일을 수정 중인 다른 실행자가 없는지 확인한다. 상태가 불명확하면 추가 쓰기를 시작하지 않는다.
2. `git diff`로 정본 버전과 비버전 필드를 확인하고 `npm run sync:check`로 남은 버전 차이를 조회한다. 검사 모드는 파일을 바꾸지 않는다.
3. 정본이 의도한 버전이며 입력 JSON이 정상일 때 `npm run sync`를 한 번 실행한다. 버전 외 필드는 현재 입력을 유지한다. 기본 버전과 날짜가 유효한 기존 Codex 빌드 값도 보존한다.
4. `npm run verify`와 diff를 확인한다. 문법 오류나 `AggregateError`가 있으면 해당 파일과 충돌을 확인한 뒤 다시 검증한다. 손상된 JSON은 자동으로 추측해 고치지 않는다.

강제 종료가 `finally` 실행을 건너뛰면 `.<파일명>.<UUID>.tmp`가 남을 수 있다. 다음 동기화는 이 파일을 입력으로 사용하지 않는다. 실행자가 모두 끝났는지와 해당 중단 실행이 만든 정확한 파일인지를 확인한 뒤에만 개별 정리한다. 이름 패턴만으로 일괄 삭제하지 않는다.

## 확보한 증거와 남은 작업

[파일 어댑터 검사](../tests/node-files.test.mjs)는 기록 실패, 데이터 반영 실패, 복구 충돌과 외부 변경 보존을 확인한다. [동기화 검사](../tests/metadata.test.mjs)는 실제 자식 프로세스를 첫 번째와 두 번째 교체 뒤 `process.exit(86)`으로 끝내 `finally`가 실행되지 않는 상황을 만든다. 다음 검사가 남은 차이만 보고하는지, 재실행이 현재 비버전 필드를 보존하며 수렴하는지와 반복 실행 시 추가 변경이 없는지를 확인한다.

이 검사는 운영체제 강제 종료, 커널 장애와 실제 전원 차단의 증거가 아니다. 전원 장애 실험은 [격리된 장애 주입 작업](todo/power-loss-durability.md)에 남긴다. 완전한 다중 파일 원자성이 필요해지면 읽기 측 프로토콜과 배포 단위 변경부터 별도 계약으로 검토한다.
