# 세션 소유권 구조

oh my teams는 Orca가 보여 주는 워크트리와 그 안의 소유 세션을 실행 단위로 사용한다. 사용자의 요청을 받은 세션이 목표, 작업 범위, 결과 검증, 전달과 종료를 책임진다. 별도의 이사나 PM 세션은 필수가 아니다.

## 소유권

- 워크트리마다 편집을 책임지는 소유 세션은 한 번에 하나다. 같은 워크트리를 읽는 서브에이전트는 소유자가 되지 않는다.
- 현재 세션이 이미 Orca 워크트리에 있으면 그 워크트리에서 계속한다. 새 워크트리는 독립적인 동시 편집이나 사용자가 요청한 별도 작업 공간에만 만든다.
- 다른 워크트리의 세션은 자신의 변경과 검사 결과를 소유한다. 부모 세션은 자식의 결과를 검증하고 통합할 책임을 가진다.
- 워크트리, 터미널, 프로세스와 실행 상태의 정본은 Orca다. OMT는 이를 복제하는 등록부, Run 또는 Dispatch 상태를 만들지 않는다.
- 소스와 전달 상태의 정본은 Git 커밋과 PR/MR이다. 대화 속 완료 선언은 검증 결과를 대신하지 않는다.

## 전문 서브에이전트

소유 세션은 필요할 때 실행기가 제공하는 서브에이전트에게 `advisor`, `lawyer`, `auditor` 작업을 맡길 수 있다. 세 작업은 상설 직책이 아니라 호출 목적이다. 이 호출만을 위해 워크트리나 터미널을 추가하지 않는다.

| 목적 | 맡길 일 | 결과를 결정하는 사람 |
|---|---|---|
| advisor | 선택지, 근거, 위험을 비교한다. | 소유 세션 |
| lawyer | 이의와 요구 사항을 대조하고 응답 초안을 만든다. | 소유 세션 |
| auditor | 고정된 커밋과 수용 기준을 읽고 결함과 누락을 찾는다. | 소유 세션. 다만 자신의 결과를 독립 검토로 가장하지 않는다. |

전문 서브에이전트는 기본적으로 읽기 전용이다. 소유 세션은 제출된 인용, 검사 결과와 변경 범위를 직접 확인한다. 독립 검토가 필수인 경우에는 구현과 다른 실행 ID로 고정된 커밋을 검토하고, 검토 결과를 소유 세션이 조용히 고쳐 승인하지 않는다. 실행기가 다른 실행 ID를 제공하지 않으면 독립 검토를 완료했다고 기록하지 않는다.

## 작업과 종료

1. 소유 세션은 사용자 요청에서 목표, 수용 기준, 제약과 전달 범위를 정한다. 불분명한 사항은 자신이 사용자에게 확인한다.
2. 순차적인 작업은 현재 워크트리에서 진행한다. 읽기 전용 조사와 검토는 직접 하거나 전문 서브에이전트를 사용한다.
3. 동시 편집이 꼭 필요할 때에만 Orca 자식 워크트리에 소유 세션을 연다. 자식에게 범위와 완료 조건을 전달하고, Orca에서 그 실행을 감독한다.
4. 소유 세션은 최신 커밋의 검사와 필요한 독립 검토를 확인한 뒤 사용자가 허가한 방식으로 전달한다.
5. 자식 워크트리를 회수하기 전에 해당 세션의 종료, 추적되지 않거나 무시된 파일을 포함한 Git 상태, 결과의 통합 여부와 정확한 Orca 워크트리·인스턴스 식별자를 확인한다. 제거 후에는 Orca에서 결과를 다시 확인한다. 증거가 불명확한 워크트리는 보존한다. 현재 세션이 서 있는 워크트리는 스스로 삭제하지 않는다.

## 이전 버전의 기록

2.x의 `.omt` 조직, kickoff, workflow와 감사 기록은 자동 변환하거나 삭제하지 않는다. 3.x 실행은 그 기록을 읽어 실행 소유권을 추정하지 않는다. 필요한 과거 자료는 Git 이력과 기존 `.omt` 디렉터리에서 읽을 수 있으며, 진행 중인 2.x 실행은 해당 버전으로 종료해야 한다.
