# macOS 실제 호스트 연동 검증

상태는 미착수다. Windows에서 확보한 결과와 Jenkins의 macOS 단위 검사는 실제 Mac 호스트 연동을 대신하지 않는다. Mac의 Orca에 접근할 수 있는 소유 세션이 인수한다.

## 준비와 실행

1. 실제 `main` SHA, macOS·Node·Claude Code·Codex CLI·Orca 버전을 기록한다. 로컬 변경을 보존하고 패키지를 설치한 뒤 `npm ci`와 `npm run verify`를 실행한다.
2. [설치 명령](../../README.md#설치)을 사용해 두 호스트의 플러그인을 설치하거나 공식 CLI로 갱신한다. 사용자 설정 파일을 직접 편집하지 않는다. 활성 설치 경로와 버전을 조회하고 설치된 스킬·참조 문서의 해시를 체크아웃과 비교한다.
3. [판단 평가 절차](../../evals/README.md#재현-방법)에 따라 두 호스트에서 사례를 실행한다. 기대값과 이전 응답은 호스트 입력에서 제외하고 각 필드의 차이를 그대로 기록한다.
4. [실제 연동 절차](../../evals/LIVE_INTEGRATION.md#재현-절차)에 따라 이름을 알려주지 않은 상태 조회의 스킬 선택을 관측한다. 새로 만든 폐기 가능한 자식만 삭제 응답 유실 검증에 사용한다. 기존 작업공간과 현재 소유 워크트리는 보존한다.
5. macOS의 임시 경로 별칭, 셸 인용과 설치 경로의 차이를 기록한다. 접근 실패는 관측 불가로 남기며 삭제 실패로 해석하지 않는다. 검증용 자식·터미널·브랜치가 남았는지 확인한다.

## 완료 기준과 결과

두 호스트의 설치 해시, 실제 정책 읽기와 스킬 선택, Orca 조회, 응답 유실 후 추가 삭제 여부 및 검증 대상의 최종 상태를 확보해야 한다. 결과는 `evals/`에 macOS 전용 Markdown과 JSON으로 추가하고 이 문서에 링크한다. JSON에는 실행 시각, 환경, 사례 ID, 입력·정책·원본 도구 기록의 SHA-256, 기대와 실제 결과, 차이와 미검증 조건을 적는다. 원본 기록은 저장소 밖에 보관하고 인증 정보와 다른 작업공간 정보는 커밋하지 않는다.

14개 판단 사례의 전부 일치와 생명주기 행동의 일치를 구분한다. 실제 전송 단절은 [별도 작업](transport-disconnect.md)이며 응답 바이트를 버린 결과로 대체하지 않는다. 현재 결과 파일과 완료 커밋은 없다.
