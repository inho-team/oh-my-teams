## 3.2.1 후속 처리와 남은 검증

#133은 3.2.1에서 기존 소스 검사에 플랫폼 독립적인 규칙을 추가해 처리했다. 테스트와 예제의 정규식 리터럴에서 고정 `/`를 거부하고, 실제 경로의 기대값은 `path.join`으로 구성하거나 두 구분자를 받는 문자 클래스를 사용하도록 진단한다. 규칙은 `npm run lint`에 포함되며 Windows CI에 의존하지 않는다. 동적 `RegExp`나 임의 문자열 비교까지 분석하지는 않는다.

회귀 검사는 이슈의 원래 정규식과 같은 고정 구분자 입력을 거부하고, `path.join`과 양쪽 순서의 구분자 문자 클래스를 허용한다. 새 테스트 파일을 추가한 임시 저장소에서도 실제 검사 진입점이 문제를 찾는다. 규칙 추가 전에는 두 검사가 실패했고 추가 후에는 통과했다. 기존 테스트의 정규식 리터럴 62개도 대조했으며 같은 경로 가정은 발견되지 않았다.

위 표는 수정 전 분류를 보존한다. 이 후속 처리를 반영하면 현재 규칙·검사에 반영된 항목은 5개이며, 당시 분류한 검사 공백 1개는 해소됐다. YAML의 LF 체크아웃 규칙과 실제 Git 회귀 검사도 같은 3.2.1 작업에 포함한다. GitHub 이슈의 종료 상태는 변경하지 않았다.

외부 호스트가 필요한 여섯 이슈는 증상을 재현한 환경에서 원본 도구 응답, 실제 터미널 상태, 버전과 최종 자원 상태를 확보해야 한다. Mac·Linux 호스트와 장애 주입에 관한 별도 인수 조건은 [후속 작업 목록](README.md)에 있다.

분류에는 인증된 `gh issue list`의 34개 본문, 현재·과거 Git 트리와 현재 스킬·소스·테스트를 사용했다. 과거 2.x 재현 기록, 실제 Orca·Agy 실행이나 백포트 결과는 검증하지 않았다. 이슈를 종료하거나 외부에 댓글을 작성하지 않았다.
