# 격리된 전원 장애 내구성 실험

상태는 미착수다. 사용자가 선택한 현재 범위는 기존 JSON 경로를 유지하는 복구 보완이다. [복구 계약](../METADATA_RECOVERY.md)의 자식 프로세스 종료 검사는 전원 장애를 대신하지 않는다. 이 작업은 파괴 가능한 VM에서 별도로 수행한다.

## 실험 범위

사용자 데이터와 실제 Orca가 없는 VM에 저장소 복사본을 준비한다. OS·파일 시스템·마운트 옵션·가상 디스크 캐시·Node 버전과 대상 SHA를 기록하고 외부에서 VM 전원을 제어한다. 호스트나 사용자의 실제 장치를 강제 종료하지 않는다.

쓰기 전, 임시 파일 기록 뒤, 데이터 반영 뒤, 각 이름 변경 뒤와 전체 완료 뒤에 강제 전원 차단을 주입한다. 시험을 위해 계측을 추가했다면 패치와 적용 SHA를 결과에 포함하고 제품 배포와 구분한다. 재부팅 후 JSON 파싱 여부, 세 버전의 조합, `sync:check`의 무변경 보고와 `sync` 재실행의 수렴 여부를 확인한다. 손상 파일은 원본 증거를 보존하며 자동으로 복구됐다고 기록하지 않는다.

## 완료 기준과 설계 결정

각 경계의 반복 횟수와 모든 결과를 `evals/`의 별도 기록에 남긴다. 실패는 사용한 파일 시스템과 저장 장치 조건에 한정해 해석한다. 디렉터리 항목 동기화가 필요하다는 증거가 나오면 OS별 지원·오류 처리·복구 실패까지 검토한 후 별도 변경을 제안한다. 여러 파일의 원자적 읽기가 필요하면 읽기 측 프로토콜 변경을 별도 결정으로 올린다. 이번 실험만으로 모든 장치의 내구성이나 다중 파일 원자성을 보장한다고 쓰지 않는다. 현재 결과 파일과 완료 커밋은 없다.
