# 다른 세션에 전달할 후속 작업

2026-10-15에 현재 Windows 세션에서 접근할 수 없는 환경과 미검증 장애 조건을 분리했다. 사용자는 Mac·Linux가 다른 Orca에 있으므로 해당 세션이 수행할 수 있게 작업별 Markdown을 남기도록 요청했다. 아래 항목은 구현 완료나 검증 성공을 뜻하지 않는다.

| 작업                                           | 상태                                           | 필요한 환경                                               |
| ---------------------------------------------- | ---------------------------------------------- | --------------------------------------------------------- |
| [macOS 실제 호스트 연동](native-host-macos.md) | 미착수이며 Mac 세션에서 인수해야 한다.         | macOS의 실제 Claude·Codex·Orca가 필요하다.                |
| [Linux 실제 호스트 연동](native-host-linux.md) | 미착수이며 Linux 세션에서 인수해야 한다.       | Linux의 실제 Claude·Codex·Orca가 필요하다.                |
| [실제 전송 단절](transport-disconnect.md)      | 미착수이며 지원되는 격리 경로를 확보해야 한다. | 폐기 가능한 Orca 대상과 관측 가능한 전송 경로가 필요하다. |
| [전원 장애 내구성](power-loss-durability.md)   | 미착수이며 별도 격리 실험이 필요하다.          | 작업 데이터가 없는 VM과 강제 전원 차단 제어가 필요하다.   |

인수하는 세션은 실제 `main` SHA, 설치 버전과 정책 해시부터 기록한다. 이 문서의 작성 버전은 3.0.8이며 미래 실행 버전을 고정하지 않는다. 작업은 해당 Orca 워크트리의 소유 세션이 수행하며 기존 세션의 기록이나 성공 여부를 추정하지 않는다. 완료 시 해당 작업 문서에 결과 파일과 커밋을 연결하고 상태를 갱신한다. 코드 변경은 종류에 맞는 브랜치에서 진행하고 병합 전에 현재 HEAD의 Linux·macOS CI를 확인한다.

## 2026-10-22 Windows 세션 재점검

[열린 이슈 34개의 적용 여부](open-issues-triage.md)를 현재 3.x 구조와 대조했다. 제거된 2.x 기능 23개, 현재 규칙·검사에 반영된 항목 4개, 플랫폼 경로 가정 탐지의 공백 1개와 외부 호스트 증거가 필요한 항목 6개로 분류했다. 이슈를 수정 완료로 일괄 처리하거나 GitHub 상태를 변경하지 않았다.

`main`을 `ee28b74`까지 받은 뒤 `fix/windows-yaml-line-endings`에서 패키지 3.2.1의 수정 작업을 진행했다. `orca host list --json`에는 로컬 Windows 호스트 하나만 표시됐고 `orca environment list --json`의 저장된 원격 환경은 비어 있었다. Mac·Linux의 실제 호스트 검증은 해당 환경의 소유 세션이 인수해야 한다. 전송 단절을 주입할 격리 대상과 전원 차단을 제어할 폐기 가능한 VM도 이번 세션에 제공되지 않아 위 네 작업은 미착수 상태를 유지한다.

Windows에서는 `.gitattributes`에 YAML의 LF 규칙이 없어 `core.autocrlf=true`인 체크아웃의 포맷 검사가 실패하는 문제를 재현했다. LF 규칙을 추가했으며, 실제 배포 YAML을 임시 Git 인덱스에서 다시 체크아웃하는 회귀 검사가 수정 전 실패하고 수정 후 통과했다. 이 로컬 검증은 위 네 환경별 검증이나 수정 브랜치의 Jenkins 검사를 대신하지 않는다.

#133의 경로 구분자 검사 공백도 같은 3.2.1 작업에서 보완했다. 테스트·예제의 고정 슬래시 정규식을 진단하고 `path.join`이나 양쪽 구분자를 받는 문자 클래스를 사용하도록 한다. 수정 전·후의 회귀 검사와 기존 정규식 62개에 대한 대조 결과는 [이슈 분류의 후속 처리](open-issues-triage.md#321-후속-처리와-남은-검증)에 정리했다.

사용자는 2026-10-22에 실제 호스트·장애 주입 검증용 환경을 현재 제공할 수 없다고 답했다. 위 네 검증은 미완료로 유지하고, 독립적으로 가능한 수정·검증과 원격 반영을 먼저 진행하기로 했다. 환경별 결과 파일이 없는 상태를 실행 성공으로 처리하지 않는다.
