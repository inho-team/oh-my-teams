# Linux 실제 호스트 연동 검증

상태는 미착수다. Jenkins의 Linux 컨테이너는 개발 도구를 검사하며 실제 Linux 호스트의 Claude·Codex·Orca 연동을 검증하지 않는다. 해당 Orca에 접근할 수 있는 Linux 소유 세션이 인수한다.

## 준비와 실행

1. 실제 `main` SHA, 배포판·커널·Node·Claude Code·Codex CLI·Orca 버전을 기록한다. 실제 호스트에서 `npm ci`와 `npm run verify`를 실행하고 컨테이너 실행 여부를 구분한다.
2. [공식 설치 명령](../../README.md#설치)으로 두 호스트의 플러그인을 준비한다. 설치 경로·활성 버전과 스킬·참조 문서의 SHA-256을 체크아웃과 비교한다. 설정 파일을 직접 수정하지 않는다.
3. [판단 평가](../../evals/README.md#재현-방법)를 두 호스트에서 실행하고 기대와 실제 응답의 차이를 기록한다. 입력에는 기대값이나 기존 결과를 포함하지 않는다.
4. [실제 연동 검증](../../evals/LIVE_INTEGRATION.md#재현-절차)의 상태 조회와 삭제 응답 유실 후 재조회를 수행한다. 격리된 검증용 자식만 사용하고 생성 응답의 전체 ID·인스턴스·부모·실행 호스트·경로를 보존한다.
5. 실행 권한, 경로 대소문자, 샌드박스와 Orca 접근 실패를 기록한다. 접근 실패만으로 기존 세션을 재생성하거나 삭제를 반복하지 않는다. 검증 자식·터미널·브랜치의 최종 상태를 확인한다.

## 완료 기준과 결과

두 호스트의 설치·정책 해시, 실제 스킬 선택과 도구 기록, 완전한 Orca 관측 및 추가 삭제 여부를 확보한다. 결과는 `evals/`에 Linux 전용 Markdown과 JSON으로 남기고 이 문서에 링크한다. 실행 시각, 환경, 사례 ID, 입력·정책·원본 기록 해시, 기대·실제 결과, 차이와 미검증 조건을 기록한다. 원본 기록은 저장소 밖에 보관하며 토큰과 다른 작업공간 정보는 커밋하지 않는다.

단위 검사 통과와 실제 호스트 통과를 따로 판정한다. 전송 장애는 [별도 작업](transport-disconnect.md)에서 수행한다. 현재 결과 파일과 완료 커밋은 없다.
