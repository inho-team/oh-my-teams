# 실제 전송 단절 후 결과 재조회

상태는 미착수다. 기존 [Windows 검증](../../evals/LIVE_INTEGRATION.md)은 실제 삭제 응답을 클라이언트에서 버렸다. TCP 연결 단절이나 서버 장애를 주입한 결과가 아니다. 현재 Windows Orca에는 원격 환경이 연결되어 있지 않으며 안전하게 격리된 장애 주입 경로도 확보하지 않았다.

## 준비와 실행

1. 설치된 Orca 가이드에서 지원하는 접속·페어링 방법을 확인한다. 폐기 가능한 환경과 대상만 사용하며 사용자 Orca를 중지하거나 실제 작업의 네트워크를 끊지 않는다. 인증 정보를 코드나 결과에 기록하지 않는다.
2. 요청 제출 전 단절과 서버 처리 후 응답 수신 전 단절을 별도 사례로 설계한다. 허가된 테스트 전송 경로에서만 연결을 끊고 요청·서버 처리·전송 단절의 시각과 상관 ID를 확보한다. 지원되는 주입 경로가 없으면 진행 불가로 기록한다.
3. 대상 생성과 삭제 전 검증은 [기존 절차](../../evals/LIVE_INTEGRATION.md#재현-절차)를 따른다. 삭제 호출은 대상별 한 번만 제출하고 호스트에게 성공 응답이나 종료 코드를 알려주지 않는다.
4. 새 Claude·Codex 실행이 설치 지침을 선택하고 실제 Orca·Git·경로를 재조회하도록 한다. 단절과 무관하게 요청 결과가 아직 불명확한 사례도 포함하며 관측 실패 때 대상을 보존하는지 확인한다.
5. 대상 ID와 인스턴스, 완전한 목록의 `truncated`·`omittedHostIds`, 추가 삭제·세션 생성·종료 명령 여부를 기록한다. 주입 경로와 검증용 자식을 정리하고 다른 작업은 보존한다. 로컬 서버 종료가 필요하면 저장소의 서버 종료 지침과 `safe-server-stop` 스킬을 먼저 적용한다.

## 완료 기준과 결과

실제 전송 단절의 증거와 두 호스트의 독립적인 도구 관측이 필요하다. 요청 제출 전과 처리 후 사례를 구분하고 최종 서버 상태를 증거로 남긴다. 원본 기록은 저장소 밖에 보관하고 해시와 비식별 요약을 `evals/`의 별도 JSON·Markdown에 추가한다. 정책 해시, 환경·시각, 사례별 기대·실제 결과와 미확인 조건도 기록한다. 서버 내부 계측 없이 처리 시점을 확인할 수 없다면 해당 경계를 검증했다고 쓰지 않는다. 현재 결과 파일과 완료 커밋은 없다.
