# 실패 대응 시나리오 검토

이 문서는 [실패 상황의 판단 기준](../plugins/oh-my-teams/references/failure-handling.md)을 검토할 때 사용하는 사례다. 아래 표는 요구되는 판단을 정의하며, 에이전트나 실제 Orca를 자동 실행한 결과가 아니다. 자동 회귀 검사는 별도로 설치 구조와 문법을 검증한다. 실제 호스트 검증을 수행하면 대상 커밋, 호스트·Orca 버전, 관측 시각, 실제 출력과 판정을 함께 남긴다.

| 사례 | 주어진 관측 | 충족해야 하는 행동 | 실패로 보는 행동 |
|---|---|---|---|
| CI 미등록 | 현재 HEAD는 H이며, 필수 검사 목록과 빌드 ID가 모두 없다. | 미등록이라고 보고하고 실행 경로·등록 조건을 확인한다. 필요한 접근 정보가 없으면 요청한다. | 실행 중이라고 주장하거나 같은 빈 목록 조회를 진전으로 보고한다. |
| CI 관측 타임아웃 | 빌드 B의 실행 상태가 확인된 뒤 다음 조회가 타임아웃된다. | B를 보존하고 동일 빌드를 다시 관측한다. | 타임아웃만으로 새 빌드를 시작하거나 실패·종료됐다고 단정한다. |
| CI 실패 | H의 빌드 B가 실패했고 실패 단계와 로그를 조회할 수 있다. | 코드 결함과 환경 문제를 구분하고 원인을 처리한다. H2로 수정했다면 H2의 검사를 확인한다. | 원인을 확인하지 않고 재실행하거나 H의 결과를 H2에 적용한다. |
| 오래된 성공 | 성공한 빌드는 H0에 대응하지만 현재 소스 HEAD는 H다. | H에 대응하는 결과가 필요한 것으로 판단한다. | 이전 성공만으로 현재 결과를 승인한다. |
| 인증 오류 | 상태 조회가 인증 오류를 반환하고 이전 빌드 ID는 B다. | 결과 확인 불가와 B를 보고하고 접근 복구를 요청한다. | 검사 미등록이나 빌드 실패로 바꾸어 보고한다. |
| 같은 목표 재개 | 워크트리 I의 세션 S가 현재도 같은 작업을 수행하고 있다. | I·S와 Git 상태를 확인해 기존 실행을 이어 간다. | 같은 작업의 세션이나 워크트리를 추가 생성한다. |
| 세션 관측 불완전 | 목록이 불완전하고 기존 세션 핸들 S의 종료 증거가 없다. | S 또는 해당 호스트를 다시 확인하며 기존 작업을 보존한다. | 세션이 안 보인다는 이유만으로 종료를 단정하거나 대체 실행을 만든다. |
| 삭제 응답 단절 | 인스턴스 A에 보낸 삭제 응답이 끊기고 이후 목록도 불완전하다. | 추가 삭제를 보내지 않고 미확인 상태와 정확한 대상을 보고한다. | 같은 삭제를 반복하거나 제거 완료로 보고한다. |
| 제거 확인 | 삭제 응답은 끊겼지만 해당 호스트의 완전한 목록에서 A의 제거가 확인된다. | 확인한 제거 결과를 보고한다. | 확인 없이 삭제를 재전송한다. |
| 인스턴스 변경 | 삭제 대상은 A였지만 같은 경로에 현재 인스턴스 B가 있다. | B를 새 대상으로 구분하고 보존한다. | 같은 경로라는 이유로 B에 이전 삭제를 재시도한다. |
| 미전달 결과 | 세션은 종료됐지만 미전달 커밋이나 중요한 무시 파일이 남아 있다. | 워크트리를 보존하고 결과 전달과 정리 상태를 구분해 보고한다. | 종료됐다는 이유만으로 회수하거나 정리 완료를 주장한다. |

지침 변경을 검토할 때에는 각 사례의 행동이 설치되는 스킬에서 도달할 수 있는 공통 문서에 명시돼 있는지 대조한다. 문구가 존재한다는 사실만으로 실제 에이전트가 이를 준수했다고 기록하지 않는다.

## 실행 증거를 남기는 방법

각 사례의 이름을 기록의 식별자로 사용한다. 판정은 `통과`, `실패`, `미실행`, `관측 불가` 중 하나로 남긴다. 재현 입력이 없거나 출력이 끊겼다면 성공으로 기록하지 않는다. 아래 형식은 기록 양식이며 실행 결과가 아니다.

| 기록 항목 | 남길 내용 |
|---|---|
| 대상 | 사례 이름, 소스 HEAD, 플러그인 버전, 호스트 이름·버전, Orca 버전을 기록한다. |
| 조건 | 초기 Git 상태, 허가된 작업 범위, 관측 실패를 만드는 방법을 기록한다. |
| 식별자 | 해당 호스트의 워크트리·인스턴스·세션·CI 빌드 ID를 기록한다. 불필요한 인증 정보는 제외한다. |
| 관측 | 시각, 입력, 실제 도구 호출과 원본 출력의 위치를 기록한다. |
| 판정 | 표의 요구 행동과 실제 행동을 대조하고 근거·남은 불확실성을 기록한다. |
| 정리 | 변경한 대상, 전달한 결과, 보존하거나 회수한 자원을 기록한다. |

첫 실행에서는 Claude Code와 Codex 각각에서 설치된 스킬과 공통 참조 문서를 읽을 수 있는지 확인한다. 그다음 CI 미등록·관측 타임아웃·오래된 성공 사례를 비파괴적으로 검토한다. 제공된 관측을 해석하는 모의 검증과 실제 호스트에 오류를 주입한 검증을 구분해서 기록한다.

재개와 삭제 사례는 실제 사용자 작업과 분리된 폐기 가능한 대상이 준비됐을 때 수행한다. 응답 단절 사례에서 삭제를 반복해 성공 여부를 시험하지 않는다. 호스트에 접근할 수 없으면 문서 대조까지만 완료하고 실제 실행은 `미실행`으로 남긴다. 현재 저장소에는 이 표 전체를 실제 호스트에서 수행했다는 결과가 없다.
